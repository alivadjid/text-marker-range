# Roadmap: надёжная библиотека текстовых выделений

## Целевой контракт

- [x] Поддерживаемый контент — произвольное DOM-содержимое: текст, вложенные inline- и block-элементы, ссылки, форматирование и иные DOM-узлы.
  Библиотека не санитизирует входной HTML: безопасность не доверенного контента остаётся ответственностью потребителя.
- [ ] Поддержать создание, восстановление, получение списка, редактирование и удаление выделений. Создание, восстановление и удаление через `handleRemoveHighlight` уже есть; редактирование и полный CRUD API остаются.
- [ ] Поддержать несколько независимых документов и экземпляров компонента на одной странице.
- [ ] Хранить выделения в стабильном сериализуемом виде, не зависящем от итоговой DOM-разметки.
- [ ] Описать поддержку браузеров, требования доступности и границу ответственности за безопасность HTML-входа.

## Зафиксированные границы пакета

- [x] `src/` содержит только исходный код библиотеки: публичный Vue-компонент, его внутренние зависимости, типы и стили, необходимые для работы компонента.
- [x] `playground/` содержит только локальное демо библиотеки: bootstrap приложения, пример потребления и демонстрационные fixtures. Код playground не является частью npm-пакета и не импортируется библиотекой.
- [x] Проверить, что Vite и TypeScript собирают пакет только из библиотечной точки входа, а изменения playground не влияют на содержимое `dist`.
- [x] Сформировать минимальный явный `exports` в `package.json`: экспортировать только документированный публичный API библиотеки и её публичный CSS entry point. Не экспортировать playground, внутренние компоненты, composables, helpers, constants или служебные типы.
- [x] Удалить из package metadata устаревшие `main` / `module` / `types` и вторичные exports, дублирующие публичный контракт.
- [x] Проверить установленный tarball через `pnpm pack`: в нём только `dist`, README и package metadata.

**Правило владения:** playground — обычный потребитель опубликованного API. Он не задаёт API, не хранит логику библиотеки и не должен получать доступ к внутренним путям `src`.

## P0 — Сделать алгоритм предсказуемым

- [x] Заменить рекурсивный алгоритм мутации DOM в `src/composables/useMarker.ts` на чистую модель диапазонов и отдельный рендерер.
  Алгоритм сначала вычисляет результат из неизменяемого исходного текста и списка диапазонов, затем один раз строит разметку. Один набор данных должен давать одну и ту же разметку независимо от порядка сохранения или восстановления выделений.
- [x] Ввести канонический формат диапазона: символьные смещения `start` и `end` в нормализованном `textContent` исходного DOM, где `start < end`.
  При необходимости сохранять структурные якоря как дополнительный механизм восстановления после изменения исходного DOM.
- [ ] Ввести версионируемую доменную модель, например: `Highlight { id, documentId, range, color, metadata? }` и `TextRange { start, end }`.
- [ ] Валидировать каждое входящее выделение перед рендером: совпадение ID документа, целые конечные смещения, допустимый цвет и границы внутри текста.
- [x] Явно определить и реализовать правила пересечений: перекрытие, вложенность, одинаковые и соседние диапазоны, приоритет цвета.
- [x] Безопасно извлекать диапазон из `Selection` для всех видов границ `Range`, включая границу элемента и вложенную inline-разметку.
- [x] Сделать восстановление независимым от порядка и безопасным при повторном вызове — без дублирующихся вложенных `span`.
- [x] Убрать модульные изменяемые `ref` из `useMarker.ts`; состоянием должен владеть конкретный экземпляр компонента/контроллера.
- [x] Явно обрабатывать пустое выделение: маркер для него не создаётся.

**Критерий готовности:** выделения переживают перемонтирование; одинаковые данные всегда рендерятся одинаково; два экземпляра не влияют друг на друга; поведение на вложенной разметке и пересечениях протестировано и описано.

## P0 — Сформировать чистый публичный API

- [ ] Типизировать публичные props и события через `defineProps<T>()` / `defineEmits<T>()`; убрать неявные `any` и небезопасные утверждения типов.
- [ ] Отделить headless-ядро от Vue-интерфейса:
  - ядро: преобразование диапазонов, валидация, нормализация, план рендера;
  - Vue-адаптер: жизненный цикл компонента и интеграция с DOM;
  - опциональный UI: палитра/поповер цветов.
- [ ] Реализовать управляемый поток данных: входной `highlights` и `update:highlights` либо отдельные события `create`, `update`, `delete`.
- [ ] Разрешить потребителю передавать цвета, подписи, ID, пользовательские метаданные, CSS-класс/стили рендера; не фиксировать палитру в библиотеке. `colors` уже поддерживает пользовательскую палитру CSS-цветов; остальные расширения остаются.
- [ ] Дать понятный API удаления/редактирования и события клика или фокуса по выделению. `handleRemoveHighlight` передаёт диапазон удаления, а публичная `subtractMarkerRange` вырезает его из пересекающихся маркеров, сохраняя их оставшиеся части. Нужны целевой выбор маркера и редактирование.
- [ ] Не управлять `localStorage` внутри библиотеки. Хранение остаётся задачей потребителя; при необходимости экспортировать serializer/validator.
- [ ] Экспортировать все публичные runtime API и типы из одной документированной точки входа.

**Критерий готовности:** библиотека используется без встроенной палитры и `localStorage`, со строгими TypeScript-типами и без знания служебных data-атрибутов.

## P1 — Улучшить взаимодействие с пользователем

- [ ] Заменить ручные флаги `mousedown` / `mousemove` на работу с Selection и при необходимости `selectionchange`.
- [x] Позиционировать меню от `getBoundingClientRect()` выбранного диапазона, учитывая края viewport и прокрутку.
- [x] Предсказуемо закрывать меню по Escape, клику вне и unmount; освобождать обработчики.
- [x] Автоматически закрывать палитру по таймеру вне её и приостанавливать таймер при наведении на палитру.
- [ ] Не блокировать штатное поведение браузера без необходимости: убрать безусловный `.prevent` на `mouseup`.
- [ ] Добавить создание выделений с клавиатуры, focus-стили, ARIA-метки и контрастные дефолтные цвета.
- [ ] Поддержать touch-выделение и проверить мобильные браузеры.
- [ ] Решить, интерактивны ли выделения; если да — использовать семантические контролы, а не анонимные `<span>`.

- [x] Оставить в `src/` только исходники пакета; любой файл в `src/` должен быть частью реализации или публичной сборки компонента.
- [x] Синхронизировать имя npm-пакета, инструкции README и имена бандлов: `vue3-highlight-text-color`.

- [ ] Явно задать package exports только для утверждённого публичного Vue-компонента, его типов и публичных стилей, если они требуются; осознанно выбрать стратегию ESM/CJS.

## P1 — Протестировать реальный контракт

- [x] Добавить unit-тесты для преобразования диапазонов, валидации и пересечений. Текущий набор `src/core/highlight.test.ts` проверяет вложенный DOM, повторный рендер, приоритет пересечений и повреждённые данные.
- [x] Добавить компонентные тесты создания, восстановления, повторного рендера и двух одновременных экземпляров. Удаление остаётся отдельной задачей публичного API.
- [ ] Добавить регрессионные фикстуры: простой текст, вложенные теги, ссылки, форматирование, emoji, суррогатные пары, combining characters, RTL-текст и нормализация пробелов.
- [ ] Добавить browser-тесты мыши, клавиатуры и touch минимум в Chromium, Firefox и WebKit.
- [x] Проверить, что повреждённые сохранённые данные обрабатываются безопасно и не портят документ.
- [ ] Добавить визуальные и accessibility-проверки палитры и итоговых выделений.

## P2 — Изменение текста и производительность

- [ ] Определить поведение при изменении исходного текста после сохранения диапазонов: отклонять устаревшие данные, мигрировать по якорям или давать потребителю hook миграции.
- [ ] Если изменяемый контент входит в контракт — добавить цитатные/контекстные якоря и детерминированный алгоритм повторного поиска; документировать уверенность и ошибки.
- [ ] Замерить рендер больших документов и множества выделений; использовать план рендера без многократной мутации всего DOM-дерева.
- [ ] Рассматривать виртуализацию только после измерений.
- [ ] Добавить SSR-safe guards: не обращаться к DOM на уровне модуля и корректно работать при гидрации.

## Рекомендуемый порядок реализации

1. Описать модель диапазона и покрыть её тестами.
2. Реализовать чистые функции нормализации и построения плана рендера.
3. Заменить `useMarker` на Vue-адаптер с локальным состоянием, использующий ядро.
4. Определить и описать управляемый API компонента, затем перенести на него демо.
5. Вынести демо из `src`, исправить сборку/типы/package metadata и добавить CI.
6. Добавить UX, доступность, кроссбраузерность и поддержку изменяемого текста.
